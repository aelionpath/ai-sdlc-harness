# Concepts

AI SDLC Harness is a repo-local, artifact-driven workflow for AI-assisted software delivery. This page defines the main terms used by the current implementation.

For the command-by-command operational guide, see [Harness Flow](harness-flow.md).

## Glossary

**Task**

The harness unit of work: a bounded AI-assisted software change that a human wants to implement, review, and verify. A task may start from a rough request, issue, bug report, requirement, incident, or design note.

**Requirement**

A specific behavior, constraint, outcome, or non-goal expected inside a task.

**Acceptance criteria**

Observable conditions used by humans to decide whether a requirement or task outcome has been satisfied.

**Task artifacts**

User-editable files under `.harness/tasks/<task-slug>/` that hold task intent and evidence notes. Current task artifacts include `task.md`, `acceptance.md`, `architecture-notes.md`, `coupling-notes.md`, `test-contract.md`, `verification.md`, and `evidence.md`.

**Preflight**

The task-readiness report created by `ai-sdlc preflight --task <task-slug>`. It summarizes shallow repository signals and task artifact readiness before implementation. It is not a semantic validator, security scanner, pack enforcement engine, or AI review.

**Spec**

The deterministic implementation-intent summary created by `ai-sdlc spec --task <task-slug>`. The command writes `spec.md` and `requirements.yaml` for the selected task.

**Advisory requirements projection**

`requirements.yaml`, generated by `spec`, is an advisory structured projection from source task artifacts. It is not authoritative. To change requirements, edit source task artifacts and rerun `spec`.

**Workset**

The generated task-scoped context package intended for a coding agent or human implementer. The current workset is `.harness/tasks/<task-slug>/generated/agent-workset.md`.

**Evidence**

Recorded implementation and review trace, including what changed, why it changed, checks run, results, known gaps, and references. Evidence supports human review but does not prove correctness, security, or compliance.

**Review readiness signals**

Blocker, warning, and info findings produced by reports such as `preflight.md`, `test-contract-review.md`, `evidence-report.md`, and `validation-report.md`. These signals guide human review; they do not approve work.

**Manifest-managed file**

A file tracked in `.harness/manifest.json` with ownership and integrity metadata. Manifest-managed generated files can be refreshed by the command that owns them. Existing unmanaged files are not automatically claimed or overwritten.

**Optional pack**

A reusable guardrail bundle for deeper concern-specific guidance. The current scaffold records that no optional packs are selected by default. Packs are not the foundation baseline and are not enforced by the current command surface.

**Verify**

The integrity check run by `ai-sdlc verify`. It checks `.harness/` structure and manifest-managed file hashes. It does not inspect implementation semantics or determine correctness.
